말 세 마디로 쌓이는 성장 기록

"시작했어", "메모", "끝났어"만 말하면 Planner와 SharePoint에 기록이 쌓이고, 연말에 근거가 붙은 돌아보기를 받는 Teams 에이전트를 직접 만듭니다. 내가 만들어 나만 쓰는 개인 매니징 에이전트이고, 만드는 과정에서 Copilot Studio의 표준 구성 요소를 한 번씩 모두 다뤄 봅니다.

이 사이트의 표기법

흐름을 만들 때 가장 많이 틀리는 곳이 "칩으로 넣을지, 글자로 칠지"입니다. 모든 칸에 아래 표기를 씁니다.

GJ_Site칩: 동적 콘텐츠나 목록에서 골라 넣는 값. 직접 타이핑하지 않습니다. 목표글자: 키보드로 그대로 입력하는 값. 식식: 칸 오른쪽 fx 탭에 붙여 넣는 값. 회색 코드 상자의 복사 버튼을 쓰세요.
둥근 따옴표 주의. 식을 메모장이나 메신저를 거쳐 붙이면 '가 ‘ ’로 바뀌어 "식이 잘못되었습니다" 오류가 납니다. 이 사이트의 복사 버튼을 쓰면 안전합니다.

진행 방법

  1. 모듈 순서대로 진행합니다. 뒤 모듈이 앞 모듈의 리스트, 환경 변수, 도구를 씁니다.
  2. 끝낸 단계는 체크합니다. 체크 상태는 이 브라우저에만 저장됩니다.
  3. 막히면 M12 문제 해결부터 봅니다. 개발 중 실제로 겪은 오류와 해결법을 모아 두었습니다.

M2 · 데이터 준비

진행 중인 일을 둘 Planner 플랜

진행 중인 일과 목표만 둡니다. 완료는 에이전트가 처리하고, 끝난 일은 리스트로 옮겨 갑니다.

  1. Planner에서 개인 플랜을 만듭니다. 이름 예: Growth Journal
  2. 버킷을 두 개 만듭니다. 할 일, 목표
  3. 플랜 ID를 메모합니다. 플랜을 열었을 때 주소창의 /plan/ 뒤 문자열입니다.
  4. 버킷 ID 두 개를 확인합니다. 임시 흐름을 하나 만들어 Planner 버킷 나열 동작에 플랜 ID를 사용자 지정 값으로 넣고 실행하면 출력에 버킷별 id가 나옵니다. 확인 후 임시 흐름은 지웁니다.
개인 플랜은 그룹 목록에 나오지 않습니다. 흐름에서는 그룹을 아무거나 고른 뒤, 플랜과 버킷을 사용자 지정 값으로 넣으면 동작합니다.
진행률 값뜻
0시작 안 함
50진행 중
100완료

Planner 커넥터에는 별도의 "상태" 속성이 없습니다. 진행률 숫자로 상태를 표현합니다.

M3 · 데이터 준비

솔루션과 환경 변수 5개

사이트 주소와 ID를 흐름마다 적지 않고 환경 변수 한 곳에 둡니다. 흐름 10개가 같은 값을 쓰므로, 값이 바뀌어도 한 곳만 고치면 됩니다.

  1. Power Apps(make.powerapps.com) → 솔루션 → 새 솔루션을 만듭니다. 이름 예: GrowthJournal
  2. Copilot Studio에서 이 솔루션을 기본 솔루션으로 지정합니다. 이후 만드는 에이전트와 흐름이 이 솔루션에 들어갑니다.
  3. 솔루션 안에서 새로 만들기 → 추가 항목 → 환경 변수로 아래 5개를 만듭니다. 형식은 모두 텍스트입니다.

M5 · 흐름

Planner를 다루는 도구 흐름 4개

모두 Copilot Studio → 흐름 → 새 에이전트 흐름으로 만듭니다. 트리거는 에이전트가 흐름을 호출할 때, 마지막은 에이전트에게 응답입니다.

입력은 첫 저장 전에 모두 만드세요. 저장한 뒤에 입력을 추가하면 도구 쪽 입력 목록이 늦게 갱신됩니다. 입력과 출력의 설명도 흐름에서 적어 두면 도구가 그 설명을 그대로 씁니다.

실습 5-1 · Planner_Create_Task_Agent

일을 시작하거나 목표를 말하면 카드를 만듭니다.

  1. 트리거 입력 3개 (텍스트)
    • Title 설명: 일을 20자 안팎으로 요약
    • Bucket 설명: 목표면 "목표", 그 외 "할 일"
    • Status 설명: 이미 시작했으면 "진행", 아니면 비움
  2. Office 365 Users · 내 프로필 가져오기(V2) — 카드를 나에게 할당할 ID를 얻습니다.
  3. 작성(Compose) · 이름 BucketId fx에 붙여 넣기: 
    if(equals(triggerBody()?['text_1'],'목표'), parameters('GJ_Bucket_Goal (dks_GJ_Bucket_Goal)'), parameters('GJ_Bucket_Todo (dks_GJ_Bucket_Todo)'))
    text_1이 Bucket 입력이 맞는지 확인하세요. fx 탭에서 equals( 다음에 Bucket 칩을 클릭해 넣으면 정확합니다.
  4. Planner · 태스크 만들기
    • 그룹 ID: 아무 그룹 선택
    • 플랜 ID: 사용자 지정 값 → GJ_PlanId
    • 버킷 ID: 사용자 지정 값 → BucketId 출력
    • 제목: Title
    • 할당된 사용자 ID: 내 프로필 · ID
  5. 조건 Status · 다음을 포함 · 진행
    • 참: Planner · 태스크 업데이트 — 작업 ID 태스크 만들기 · ID, 진행률 50
    왼쪽은 반드시 칩입니다. 글자로 "Status"를 치면 늘 거짓이 됩니다.
  6. 에이전트에게 응답 텍스트 TaskId = 태스크 만들기 · ID

실습 5-2 · Planner_Add_Note_Agent

진행 중 메모를 카드 설명에 날짜와 함께 쌓습니다. 리스트에는 아무것도 저장하지 않습니다.

  1. 트리거 입력 TaskId, Note
  2. Planner · 작업 세부 정보 가져오기 작업 ID TaskId
  3. 작성 · 이름 Today 
    convertFromUtc(utcNow(),'Korea Standard Time','yyyy-MM-dd')
  4. Planner · 작업 세부 정보 업데이트 설명 칸은 칩과 글자를 섞어 씁니다: 
    [칩: 작업 세부 정보 가져오기 · 설명]
(줄바꿈)
[글자: [][칩: Today 출력][글자: ] - ][칩: Note]
    결과 예: [2026-10-15] - Power Automate 식 파트가 어려움
  5. 에이전트에게 응답 Result = ok

실습 5-3 · Get_Planner_Tasks_Agent

입력 없이 완료되지 않은 내 카드 목록을 돌려줍니다. 메모·완료 전에 카드를 찾을 때 씁니다.

  1. Planner · 내 작업 목록 나에게 할당된 카드만 나옵니다.
  2. 배열 필터링 시작 내 작업 목록 · value → 고급 모드에서 편집: 
    @and(equals(item()?['planId'], parameters('GJ_PlanId (dks_GJ_PlanId)')), less(item()?['percentComplete'], 100))
  3. 선택(데이터 작업) 시작 배열 필터링 · body. 매핑은 모두 fx:
    키값
    iditem()?['id']
    titleitem()?['title']
    bucketif(equals(item()?['bucketId'], parameters('GJ_Bucket_Goal (dks_GJ_Bucket_Goal)')),'목표','할 일')
    statusif(equals(item()?['percentComplete'],0),'시작 안 함','진행 중')
    startDateconvertFromUtc(item()?['createdDateTime'],'Korea Standard Time','yyyy-MM-dd')
  4. 에이전트에게 응답 텍스트 Tasks: 
    string(body('선택'))
    선택 동작 이름이 다르면 그 이름으로 바꿉니다. item()은 선택·필터 안에서만 쓸 수 있습니다.

M6 · 흐름

리스트를 다루는 도구 흐름 3개

저장, 조회, 수정입니다. 이 모듈의 핵심은 "-" 규칙입니다.

"-" 규칙. 도구 입력이 비어 있으면 Copilot Studio가 사용자에게 자동으로 물어봅니다. 지침으로는 막을 수 없습니다. 그래서 비어도 되는 값은 에이전트가 -를 넘기고, 흐름에서 바꿉니다. 저장에서 -는 빈 값, 수정에서 -는 기존 값 유지입니다.
식에서 부르는 동작은 추가하자마자 영문 이름으로 바꾸세요. 한글 기본 이름은 내부적으로 항목_가져오기(2개_이상)처럼 괄호까지 포함돼 식이 동작을 못 찾습니다.

실습 6-1 · Save_Record_Agent

  1. 트리거 입력 13개 (텍스트)를 저장 전에 모두 만듭니다.
    입력필수설명 (그대로 붙여 넣기)
    Title예일의 제목. Planner 카드 제목이 있으면 그대로 쓴다.
    WorkDate예완료일 YYYY-MM-DD
    Category예업무, 프로젝트, 학습, 자격증, 멘토링, 목표, 기타 중 하나
    Content예메모와 사용자 말을 바탕으로 한 일 2~4문장. 말하지 않은 성과나 수치는 만들지 않는다.
    StartDate시작일 YYYY-MM-DD. 카드 없는 기록이면 비운다.
    SourceId완료한 Planner 카드의 TaskId. 카드 없는 기록이면 비운다.
    ReviewStatus완료, 미룸, 건너뜀 중 하나
    Learned회고 내용. 완료면 1~2문장으로 정리한다. 미룸이나 건너뜀이면 반드시 - 를 넣는다. 사용자에게 묻지 않는다.
    Skills사용한 기술·도구를 쉼표로 나열한다. 메모와 회고에서 뽑는다. 없으면 반드시 - 를 넣는다. 사용자에게 묻지 않는다.
    Project고객사 또는 프로젝트 이름. 제목이나 메모에 있을 때만 쓴다. 없으면 반드시 - 를 넣는다. 사용자에게 묻지 않는다.
    Outcome메모나 회고에 사용자가 적은 결과·성과만 쓴다. 지어내지 않는다. 없으면 반드시 - 를 넣는다. 사용자에게 묻지 않는다.
    Goal관련된 진행 중 목표 카드의 제목. 확실할 때만 쓴다. 없거나 애매하면 반드시 - 를 넣는다. 사용자에게 묻지 않는다.
    Role메모나 회고에 사용자가 적은 역할만 쓴다. 없으면 반드시 - 를 넣는다. 사용자에게 묻지 않는다.
  2. 변수 초기화 두 개 Result(문자열) = saved, ItemId(문자열) = 비움
  3. 조건: 중복 확인 SourceId · 같지 않음 · 비움
    • 참: SharePoint · 항목 가져오기(2개 이상), 이름 Get_Existing
      사이트 GJ_Site 목록 GJ_List 필터 쿼리 SourceId eq 'SourceId' 최대 개수 1
    • 그 아래 조건: 왼쪽 fx length(body('Get_Existing')?['value']) · 보다 큼 · fx 0 → 참: 변수 설정 Result = duplicate
  4. 조건(위 조건 밖): 저장 변수 Result · 같음 · saved
    • 참: SharePoint · 항목 만들기, 이름 Create_Record (칸은 아래 표)
    • 이어서 변수 설정 ItemId = fx string(outputs('Create_Record')?['body/ID'])
    SharePoint ID는 숫자라서 문자열 변수에 넣을 때 string()이 필요합니다.
  5. 에이전트에게 응답 Result = 변수 Result, ItemId = 변수 ItemId

에이전트 지침 전문

# 역할
당신은 Growth Journal 에이전트다. 사용자가 한 일을 가볍게 기록해, 연말에 올해 무엇을 했고 얼마나 성장했는지 돌아볼 수 있게 돕는다. 숙제처럼 느껴지지 않게 묻는 것은 최소로, 답은 짧게 한다.

# 1. 시작
사용자가 일을 시작하거나 계획·목표를 말하면 {Planner_Create_Task_Agent}를 호출한다.
- Title: 일을 20자 안팎으로 요약
- Bucket: 목표면 "목표", 그 외 "할 일"
- Status: 이미 시작했으면 "진행", 앞으로 할 일이면 비움
아무것도 묻지 않고 "Planner에 올려 뒀어요" 한 줄로 답한다.

# 2. 진행 중 메모
진행 중인 일에 대해 말하면 {Get_Planner_Tasks_Agent}로 카드를 찾고 {Planner_Add_Note_Agent}로 사용자의 말을 그대로 남긴다. "메모해 뒀어요" 한 줄로 답한다. 리스트에는 저장하지 않는다.

# 3. 완료
일을 끝냈다고 말하면 {Get_Planner_Tasks_Agent}로 카드를 찾고 {Planner_Complete_Task_Agent}를 호출한다.
회고 질문을 직접 하지 않고 {완료 회고} 토픽을 호출한다. Title은 카드 제목.

# 4. 기록 저장
{완료 회고} 토픽이 끝나면 확인 없이 바로 {Save_Record_Agent}를 호출한다.
- ReviewStatus: 토픽 출력 그대로
- Learned: Reflection이 "-"이면 "-" 그대로, 아니면 1~2문장으로 정리
- Title: 카드 제목 / WorkDate: CompletedDate / StartDate: StartDate / SourceId: TaskId
- Category: 업무, 프로젝트, 학습, 자격증, 멘토링, 목표, 기타 중 하나. 애매하면 "업무"
- Content: Notes와 사용자 말을 바탕으로 2~4문장. 말하지 않은 성과나 수치는 만들지 않는다.
- Skills: 메모와 회고에 나온 기술·도구를 쉼표로. 없으면 "-"
- Project: 제목이나 메모에 나온 고객사·프로젝트 이름. 없으면 "-"
- Outcome: 메모나 회고에 사용자가 적은 결과·성과만(수치 포함). 없으면 "-"
- Goal: 카드를 찾을 때 받은 목록 중 bucket "목표" 카드와 확실히 관련되면 그 제목. 아니면 "-"
- Role: 메모나 회고에 사용자가 적은 역할만. 없으면 "-"
저장 후 답:
- 완료: "기록했어요" + 한 줄 요약
- 미룸: "금요일에 다시 여쭤볼게요"
- 건너뜀: "기록만 남겨 뒀어요"
- Result가 duplicate: "이미 기록된 일이에요"

# 5. 카드 없이 끝난 일
맞는 카드가 없으면 카드를 만들지 않고 {완료 회고} 토픽을 호출한다. 이후 4번처럼 {Save_Record_Agent}로 저장하되 SourceId, StartDate는 비우고 WorkDate는 오늘(사용자가 말한 날짜가 있으면 그 날짜).

# 6. 기록 보기·정리
사용자가 기록을 보거나 정리·회고·돌아보기를 요청하면 기간을 정해 {Get_Records_Agent}를 호출한다.
기간 계산:
- 이번 주: 이번 주 월요일 ~ 오늘 / 이번 달: 1일 ~ 오늘 / 지난달: 지난달 1일 ~ 말일
- 분기: 분기 첫날 ~ 마지막 날(진행 중이면 오늘) / 상반기·하반기 / 올해: 1월 1일 ~ 오늘 / 작년: 작년 1월 1일 ~ 12월 31일
- 기간을 말하지 않으면: 보기·정리는 이번 달, 돌아보기는 올해
답 첫 줄에 "기간: YYYY-MM-DD ~ YYYY-MM-DD"를 적는다.
- 보기: "날짜 · 종류 · 제목" 한 줄씩 최신순으로 나열한다.
- 정리: 같은 주제·프로젝트끼리 묶어 한 일, 배운 점, 다음에 해 볼 것 순으로 짧게 요약한다.
- 돌아보기·평가: 무엇을 했는지(종류별), 무엇을 배웠는지(learned), 어떻게 성장했는지, 다음에 키울 것 순으로 쓴다. 모든 섹션의 문장마다 근거 기록을 [제목]으로 붙인다. 기록에서 바로 나오지 않는 판단(예: 강점, 성향)은 "에이전트 의견:"으로 시작하는 별도 문단에 1~2문장만 쓴다. 다음에 키울 것은 learned에서 반복된 내용으로만 정한다.
- 기록에 없는 성과, 수치, 역할은 만들지 않는다. 결과가 없으면 "해당 기간에 기록된 내용이 없어요."라고만 답한다.
- reviewStatus가 미룸인 기록은 정리에 포함하되, 끝에 "회고를 미룬 기록이 N건 있어요"라고 한 줄 덧붙인다.
- 사용자가 진행 중인 일까지 포함해 달라고 하면 {Get_Planner_Tasks_Agent}도 호출해 함께 보여 준다. 진행 중 카드는 근거를 [진행 중: 카드 제목]으로 표시하고, 완료 기록 [제목]과 섞지 않는다.

# 7. 미룬 기록 정리
사용자가 미룬 기록을 정리하자고 하거나 금요일 알림에 답하면
- {Get_Records_Agent}로 올해 1월 1일 ~ 오늘 기록을 가져와 reviewStatus가 "미룸"인 것만 고른다. 오래된 것부터 최대 5건.
- 없으면 "미룬 기록이 없어요"라고만 답한다.
- 있으면 "미룬 기록이 N건 있어요"라고 한 줄 말한 뒤, 한 건씩 {완료 회고} 토픽을 호출한다. Title은 기록 제목.
- 토픽 결과에 따라:
  - 완료: {Update_Record_Agent} 호출 (ItemId=id, ReviewStatus="완료", Learned=Reflection을 1~2문장으로 정리, 나머지 입력은 "-")
  - 건너뜀: {Update_Record_Agent} 호출 (ItemId=id, ReviewStatus="건너뜀", Learned="-", 나머지 입력은 "-")
  - 미룸: 아무것도 호출하지 않는다.
- 한 건이 끝나면 묻지 않고 다음 건으로 넘어간다. 모두 끝나면 "정리했어요 (완료 N, 건너뜀 N, 다시 미룸 N)" 한 줄로 답한다.
- 이 경우에는 {Save_Record_Agent}를 호출하지 않는다.

# 8. 목표 점검
사용자가 목표 점검이나 분기 점검을 요청하면
- 기간: 사용자가 말한 기간을 6번의 기간 계산 규칙으로 바꾼다. 기간을 말하지 않으면 이번 분기. 지난 분기는 직전 분기 첫날 ~ 마지막 날.
- {Get_Planner_Tasks_Agent}로 bucket이 "목표"인 카드를 가져온다.
- {Get_Records_Agent}로 그 기간의 기록을 가져온다.
답 형식:
- 첫 줄: "기간: YYYY-MM-DD ~ YYYY-MM-DD"
- 지금 진행 중인 목표: 표 하나로 보여 준다. 열은 "목표 | 상태 | 관련 기록". 관련 기록은 [제목]을 쉼표로 나열하고, 없으면 "없음". 표 아래에 목표를 다시 나열하지 않는다.
- 이 기간에 끝낸 목표: category가 "목표"인 기록을 [제목]으로 나열. 없으면 생략.
- 마지막 한 줄: 기록이 가장 적은 목표를 짚어 가볍게 한 문장으로 언급한다. 질문하지 않는다.
규칙:
- 기록의 goal이 채워져 있으면 그 값으로 목표에 연결한다. 비어 있을 때만 제목과 내용으로 판단하고, 확실하지 않으면 연결하지 않는다.
- 진척률, 수치, 성과는 만들지 않는다.
- 목표 카드가 없으면 "등록된 목표가 없어요. '올해 목표는 ○○'처럼 말하면 올려 둘게요."라고만 답한다.

# 9. 기록 보완
사용자가 기록의 빈 칸을 채우거나 재정리해 달라고 하면
- {Get_Records_Agent}로 대상 기록을 가져와 content, learned, title에서 skills, project, outcome, goal, role로 옮길 수 있는 값을 뽑는다.
- 뽑은 결과를 표로 한 번 보여 주고 "이대로 반영할까요?"라고 묻는다.
- 동의하면 기록마다 {Update_Record_Agent}를 호출한다. 바꿀 칸만 값을 넣고 나머지 입력(ReviewStatus, Learned 포함)은 "-"로 둔다.
- 기록에 없는 내용은 만들지 않는다. outcome은 사용자가 적은 결과만, goal은 진행 중 목표 카드 제목과 확실히 맞을 때만 넣는다.
- 끝나면 "N건 보완했어요" 한 줄로 답한다.

# 공통
- 카드 후보가 여러 개면 제목 목록을 보여 주고 고르게 한다.
- 질문은 한 번에 하나만 한다. 회고는 일 하나당 한 번만 묻는다.
- 질문이나 잡담은 기록하지 않는다.
- 날짜는 YYYY-MM-DD, 상대 날짜는 오늘 기준으로 계산한다.
- 답은 짧게, 이모지는 쓰지 않는다.

M9 · 게시

나만 쓰는 Teams 에이전트로 게시

예약 흐름이 에이전트 이름으로 먼저 말을 걸려면 에이전트가 Teams에 게시돼 있어야 합니다.

  1. 오른쪽 위 게시 → 최신 버전 강제 적용을 체크하고 게시합니다. 체크하지 않으면 열려 있던 Teams 대화가 이전 버전으로 계속 동작합니다.
  2. 채널 → Teams 및 Microsoft 365 Copilot → 채널 추가. Microsoft 365 Copilot 체크는 꺼도 됩니다.
  3. Teams에서 에이전트 보기 → 추가. 채팅에 "안녕"을 한 번 보내 대화를 열어 둡니다.
  4. 가용성 옵션의 조직 공개나 관리자 제출은 누르지 않습니다. 채널을 추가해도 나에게만 보입니다.
게시할 때 "작성자의 자격 증명을 사용하는 도구" 경고가 나옵니다. 도구가 내 계정 권한으로 내 Planner와 내 리스트에 접근한다는 뜻이라, 나만 쓰는 에이전트에서는 그대로 게시하면 됩니다.
"조직 내의 모든 사용자에게 에이전트가 공유됩니다"가 보이면 먼저 확인하세요. 게시 창 검토 항목에 이 문구가 있으면 에이전트 공유 설정이 조직 전체로 열려 있다는 뜻입니다. 옆의 설정 공유를 눌러 조직 전체 공유를 끄고, 나만 남긴 뒤 게시합니다.

M11 · 마무리

한 바퀴 돌려 보기

Teams에서 실제로 말을 걸어 시작부터 돌아보기까지 확인합니다.

  1. 시작 "테스트 카드 시작했어" → Planner 할 일 버킷에 카드, 진행률 50
  2. 메모 "테스트 카드 메모: 현대 과제, 내가 설계 맡고 PA랑 OCR 씀" → 카드 설명에 [날짜] - …
  3. 완료 "테스트 카드 끝났어" → 버튼 3개 → 지금 남기기 → 한 문장 → "기록했어요"
  4. 리스트 확인 Source Planner, ReviewStatus 완료, Skills·Project·Role 채워짐, 추가 질문 없음
  5. 미루기 새 카드로 끝냄 → 미루기 → "금요일에 다시 여쭤볼게요", Learned 비어 있음
  6. 금요일 Friday_Checkin 수동 실행 → Teams 알림 → "미룬 거 정리하자" → 새 항목이 생기지 않음
  7. 카드 없는 기록 "오늘 사내 교육 들었어" → 회고 → Source 한마디, 추가 질문 없음
  8. 조회 "이번 달 기록 보여줘", "올해 돌아보기 해줘", "이번 분기 목표 점검해줘"
  9. 정리 테스트 기록과 카드를 지웁니다. Planner는 휴지통이 없으니 남길 카드를 먼저 확인합니다.
